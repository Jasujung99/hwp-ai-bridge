# 기존 문서의 편집 보기와 서식 검토

이 절차는 **hwpctl 직접 모드**용입니다. safe 엔진으로 기존 파일을 열거나,
두 엔진이 같은 문서를 번갈아 수정하는 절차가 아닙니다.

## 기능 기준

`set_edit_marks`는 hwpctl의 `sync/edit-marks-format-audit` 통합 브랜치,
커밋 `d0f1141d05f5d3746d03106c9f8a9cc757e49d19`에 추가된 기능입니다.
아직 출시 버전이나 기본 main 설치에 포함되었다고 가정하지 마세요.
설치된 서버의 도구 목록에 `set_edit_marks`가 있는지 먼저 확인합니다.

## 검토 순서

1. 원본 대신 복사본을 대상으로 선택하고 `status`의 문서 경로·창을 확인합니다.
2. `set_edit_marks(control_marks=true, paragraph_marks=true)`로 조판부호와
   문단부호를 표시합니다. 반복 호출해도 켜짐/꺼짐이 뒤집히지 않습니다.
3. 빈 문단처럼 보여도 표·그림·글상자의 앵커인지, 쪽 나눔을 담는지 확인합니다.
   보이는 글자가 없다는 이유만으로 삭제하지 않습니다.
4. 삭제가 필요한 경우 대상과 보존할 개체를 먼저 확정합니다. 보기 명령 자체는
   삭제나 서식 정리를 수행하지 않습니다.
5. 다른 경로에 저장하고 다시 열어 쪽 수·본문·표·그림을 검사합니다. 출력 검수는
   편집 가능한 원본 문서의 구조 검사를 대체하지 않습니다.

필요하면 `set_edit_marks(control_marks=false, paragraph_marks=false)`로 표시를
끕니다. 보기 설정은 본문 변경이나 문서 Undo 단위가 아닙니다.

## 자동화의 범위

- hwpctl의 내부 `compact_formatting_xml` 함수는 미사용 글자·문단 서식 정의와
  그 참조를 검사하는 순수 함수입니다. 공개 MCP 파일 수정 명령이 아닙니다.
- 문단·필드·그림·표는 이 함수로 삭제하지 않습니다. HWPX를 보정한 결과를
  한/글 네이티브 편집만으로 완성한 결과라고 표시하지 않습니다.
- 원본 문서·개인정보·낙관·로컬 프로필·임시 출력물은 공개 예제로 업로드하지 않습니다.
- 생성 이미지는 해당 AI 클라이언트의 이미지 도구가 만드는 자산입니다.
  이 연결 허브나 safe 엔진이 이미지 생성 API를 제공하는 것은 아닙니다.

`hwp-live-safe`는 기존의 새 문서 소유권, 미리보기·승인, 변경 감지와 제한된 Undo
경계를 유지합니다. 이 hwpctl 기능 추가 때문에 safe에 파일 열기·삭제·내보내기
권한이 생기지 않습니다. [작업 모드](modes.md)를 함께 확인하세요.
