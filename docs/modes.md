# 작업 모드

## 직접 모드

[`hwpctl`](https://github.com/Jasujung99/hwpctl)이 사용자가 열어 둔 한글 문서를 직접
조작합니다.

적합한 작업:

- 표의 빈 칸 채우기
- 제목·선택 영역의 글꼴, 색, 정렬 변경
- 짧은 문단 삽입
- 새 이름으로 저장

장점은 빠른 반영이고, 주의점은 열린 문서·선택 영역·Undo 동작을 실제 화면에서
확인해야 한다는 것입니다. 첫 사용은 복사본에서 검증하세요.

## 안전 모드

[`hwp-live-safe`](https://github.com/Jasujung99/hwp-live-safe)가 새로 연 자동화 소유
문서에서 작업합니다.

적합한 작업:

- 이력서·자기소개서 초안
- 개인정보를 로컬 프로필에서 넣는 작업
- 장문 수정안 비교
- 적용 전 검토가 필요한 문서 작성

이 모드는 미리보기와 승인, 문서 변경 감지를 우선합니다. 원래 열어 둔 임의의 문서에
자동으로 붙어 수정하는 기능을 약속하지 않습니다.

## 혼합 모드

기존 문서의 조판·문단 표시와 빈 서식 검토는
[직접 모드 편집 검토](edit-review.md)를 참고하세요. 이 기능은 safe의 권한을 확장하지 않습니다.

두 서버를 모두 AI 클라이언트에 등록합니다. 사용자는 작업마다 다음처럼 말할 수 있습니다.

> 이력서 문장은 먼저 수정안을 보여줘. 승인하면 지금 열린 문서의 선택 영역에만 적용해.

현재 혼합 모드는 **운영 방식**입니다.

1. 혼합 모드에는 공존 수정이 포함된 `hwp-live-safe` 커밋 `384f84e` 이상을 사용합니다.
   `v0.3.0-rc.1`은 한글 창이 하나라도 열려 있으면 시작을 거부하므로, 그 버전에서는
   모든 창을 닫고 안전 모드를 사용한 뒤 다시 닫고 직접 모드를 여는 순차 운용만
   가능합니다.
2. AI와 사용자가 이번 작업의 대상이 안전 엔진의 새 문서인지, 직접 엔진의 열린
   문서인지 확인합니다. 안전 문서 작업은 `hwp-live-safe`의 미리보기·승인 흐름을
   사용합니다.
3. 안전 문서에서 직접 문서로 넘어갈 때는 원하는 사용자 문서 창을 화면에서
   활성화하고 `hwpctl open`을 인자 없이 호출해 활성 창을 다시 고정합니다.
4. `hwpctl status`의 `window_title`/`path` 또는 `hwpctl list_documents`를 확인합니다.
   `unsaved: true`인 안전 엔진 문서가 아니라 의도한 사용자 문서임을 확인한 뒤에만
   직접 편집합니다.
5. 혼합 모드에서 `hwpctl close_all --force`를 사용하지 않습니다. 이 명령은 안전 엔진
   문서와 인스턴스까지 닫아 워커의 COM 참조를 무효화할 수 있습니다. 고정된 직접
   문서만 `hwpctl close --force`로 닫습니다.
6. 안전 문서는 사용자가 한글에서 직접 닫습니다. 닫은 뒤 다시 안전 문서를 시작하려면
   `hwp-live-safe` MCP 서버를 재시작합니다.
7. 다음 엔진을 호출하기 전에 사용자가 한글 화면에서 결과와 대상 문서를 확인합니다.

아직 구현되지 않은 것:

- 두 엔진 간 문서 본문의 자동 전달
- 공용 변경 이력과 공용 Undo
- 같은 한글 창에 대한 프로세스 수준의 공용 잠금
- 안전 모드가 열린 기존 문서의 상태를 자동 검증하는 기능

따라서 혼합 모드에서는 한 번에 한 엔진만 사용합니다. 안전 엔진의 승인 결과가 직접
엔진으로 자동 전달된다고 가정하지 말고, 직접 모드를 호출할 때 대상 문서·선택 영역·실행
내용을 다시 확인하세요.

Undo도 엔진별로 격리됩니다. 같은 문서를 두 엔진이나 사용자가 번갈아 수정한 뒤
`hwpctl undo`를 실행하면 가장 최근의 상대 편집부터 되돌릴 수 있습니다.
`hwp-live-safe`는 예상 지문이 달라지면 `DOCUMENT_CHANGED`로 자동 Undo를 거부합니다.
교차 편집이 발생했다면 어느 엔진의 Undo도 호출하지 말고, 화면을 확인하면서 한글의
Ctrl+Z를 직접 사용하세요.
